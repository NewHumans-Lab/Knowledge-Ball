# iOS host

The iOS application is a thin Capacitor 7 host. Knowledge Ball's root Web source is the only product implementation; the iOS target must not contain a native copy of its UI, Three.js scene, domain model, protocol, or interaction logic.

## Packaging chain

```text
root Web source -> CAPACITOR_BUILD=true npm run build -> dist/
                -> npx cap sync ios -> App/App/public/ -> WKWebView
```

`App/App/public`, `capacitor.config.json`, `config.xml`, Pods, and generated Cordova plugin shims are intentionally ignored. They are regenerated by Capacitor rather than committed. After every sync, run:

```sh
node ios/scripts/verify-packaged-assets.mjs
```

The verifier enumerates both trees deterministically and compares the relative paths and SHA-256 content hashes of every production asset. The only permitted packaged extras are Capacitor's empty `cordova.js` and `cordova_plugins.js` compatibility shims.

## Frozen-shell migration inventory

The pre-migration project was audited against a clean `@capacitor/ios` 7.6.8 generation. It contained no Knowledge Ball Swift/Objective-C product implementation and no legacy native screen to preserve or delete: `AppDelegate.swift`, the bridge storyboard, launch storyboard, Podfile, workspace metadata, and project layout all matched the current generated shell. Regeneration therefore deliberately preserves those minimal host files, the existing `org.knowledgeball.app` bundle identity, version `0.2.0`/build `2`, and the existing icon/splash assets. Generated packaged Web files remain excluded instead of becoming a stale second source.

The only native test code is `AppUITests/KnowledgeBallUITests.swift`. It launches the installed simulator application and exercises the real packaged WKWebView; it does not implement product behavior.

## Simulator acceptance

`ios/scripts/run-simulator-parity.sh` is the reproducible iOS-only gate: it builds without signing, then runs the UI smoke test on an iPhone 16 Simulator. The smoke covers WKWebView launch, a populated Web/3D surface, visible settings, localization controls, search input, node-detail open/close ownership, create validation visibility, lifecycle resume, and screenshot capture. The gate also captures a fixed 393x852 Web baseline and checks the simulator screenshot with documented tolerance for the iOS status/home bands and WKWebView font/GPU rasterization.

Run the principal macOS gates with:

```sh
CAPACITOR_BUILD=true npm run build
npx cap sync ios
node ios/scripts/verify-packaged-assets.mjs
cd ios/App
xcodebuild -workspace App.xcworkspace -scheme App -sdk iphonesimulator -configuration Debug CODE_SIGNING_ALLOWED=NO build
xcodebuild test -workspace App.xcworkspace -scheme App -destination 'platform=iOS Simulator,name=iPhone 16,OS=latest'
```
